# Brief: README style gallery — "Agree on the content first" in one style

Agreed with the user on 2026-11-01 (README key visual, gallery of styles).

## Audience
Someone reading the GitHub README of aws-samples/sample-spec-driven-presentation-maker. Just below the
animated key visual they see the same slide drawn in seven styles and decide the tool can match their look.

## What they should believe or do afterwards
- The same spec can be built in any style; the style changes how the slide looks, not what it says.

## How the deck is seen
As one tile of a 7-tile image in the README, about 220 px wide. Nobody presents it. The slide must read at a
glance as this style: its frame, its components, its density.

## Language and length
English. 1 slide: slide 3 of the key visual deck (`docs/assets/src/hero/deck-en`), same wording.

## Constraints
- Headline and supporting line are fixed wording, approved by the user; use them verbatim.
- No internal tool names or protocol names on the slide.
- No invented numbers or claims; only what is true of the product today.
