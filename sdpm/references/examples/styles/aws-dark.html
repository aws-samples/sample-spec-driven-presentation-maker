Rules / identity
Category color identifies services; it never decorates the page
Use full color for identity
Put category color on a group border, header band, legend swatch, or small category label. Readers learn the mapping once and scan every architecture faster.
Never use it as decoration
A decorative purple rule or pink headline falsely signals a service category and slows diagram decoding.
Use tint for group fills
Use the matching --cat-*-tint behind services, normal --color-text on every tint, and full color only for border or small header.
Keep all other color minimal
Beyond ground and text, add only colors that distinguish content. More color invents categories the message does not contain.
Rules / composition
One claim, one orange emphasis, and one readable route
Message
Use one full-sentence finding, sentence case, at most two lines. A claimless architecture is a map without a legend.
Emphasis
Use Smile Orange once: one number, node, current step, or title rule. If content carries orange, the title rule stays neutral; two spots read as two alerts.
Icons
Services use official icons from search_assets, source aws. Generic concepts use general icons. Align icon and short label on a grid; use ground or tint, never a card.
Readability
Keep contrast ≥ 4.5:1, or ≥ 3:1 at 18pt+. Keep margins at least 5% of the edge. Never use emoji.
Charts
Label values directly; remove gridlines without information. Use tables for exact lookup and charts for shape or change.
Renderer limits
Native tables inherit the template font. Slide JSON has no letter-spacing, line-height, or weight 650; use regular or bold and explicit box heights.

Message and outline / grammar
Finding-led titles make technical choices unambiguous
Use complete findings
“Managed services remove operating steps”
“Access tiers make storage cost follow demand”
“One event path decouples every consumer”
Avoid topic labels
“Target architecture”
“Cost overview”
“Service comparison”
Favor literal visual forms
Number:one metric or labeled KPI row.
Comparison:aligned rows or hairline table.
Process:numbered phases with named services.
Relationship:grouped architecture with orthogonal connectors.
Use prose sparingly
A short claim plus three proof points. Add prose only for a necessary qualification or supplied source note.
Avoid visual noise
No decorative circles, gradients, shadows, glow, 3D, diagonal connectors, unlabeled charts, or cards around service icons.
