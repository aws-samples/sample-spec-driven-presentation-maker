01 / Rules
Technical evidence must remain legible under review
DO / because structure is the evidence
Use one assertion title. Reviewers see the conclusion before parsing evidence.
Make code or the diagram largest. Prose only annotates the primary technical artifact.
Use mono for identifiers and metrics. Stable widths make syntax and values comparable.
Reserve semantic hues for named states. Colour then retains operational meaning.
DON'T / because effects obscure meaning
No glow, gradient, or cyber effects. Value contrast keeps syntax and lines calm.
No decorative icons or colourful cards. Extra symbols invent false categories.
Use mono for code. Proportional type breaks character-level comparison.
Never centre or pair code blocks. Code needs one stable edge and one reading path.
Audience: engineers in live or shared review. One claim; margins ≥ 5%; text contrast ≥ 4.5:1 (3:1 at ≥ 18pt); direct chart labels; no emoji; neutrals + cyan + at most one named state hue.
01 / Rules / renderer facts
Build technical structure with properties the slide renderer supports
Tables
Choose precision or capacity
Native tables inherit the template font and have no per-table family. Use aligned mono text rows for 3–6 rows; for 7–10, use a native table and accept its font.
Shapes
Keep the geometry flat
Leave shadows off (never set `shadow`); use rectangular fills, hairline borders, and straight connectors.
Type mapping
Approximate HTML refinements
Slide JSON has no letter-spacing, line-height, or weight 650. Use bold for 650 and explicit box heights for rhythm; the template supplies PPTX fonts.
HTML refines the gallery preview; slide JSON carries the supported structural approximation.

Pattern / trade-off
The durable queue is chosen because burst isolation outweighs immediacy
Chosen / durable queue
Capacity is independently bounded
isolation — ingress accepts bursts without matching worker concurrency.
recovery — retries resume from a durable position.
cost — completion becomes eventually visible.
Accepted: one component; asynchronous status.
Rejected / synchronous call
The request waits for compute
isolation — request capacity and worker capacity remain coupled.
recovery — caller retries can duplicate work.
benefit — completion is immediate on success.
Rejected: simplicity does not satisfy the burst boundary.
Decision rule: choose against the named constraint, then record the cost accepted by the chosen path.
